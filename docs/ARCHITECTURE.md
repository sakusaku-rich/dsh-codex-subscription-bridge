# Direct subscription connection

## Decision

The provider uses a direct subscription connection. The dedicated device-code OAuth login owns its own token lifecycle; Codex credentials are not imported. Initial features are model selection, text conversations, Harness tool passthrough, user message image input, streaming, cancellation, and server-side compaction.

The dedicated login implements OAuth, refresh, and store locking rather than requiring a Codex process for ordinary turns. Importing existing refresh tokens creates a shared rotation family, even when copies live in different files; dedicated login avoids that coupling.

## Transport

Only `https://auth.openai.com` OAuth/device endpoints and `https://chatgpt.com/backend-api/codex` model/Responses endpoints are used. Redirects are rejected. No custom host, raw token, proxy endpoint, arbitrary request override, shell, or Codex process is accepted in public configuration. The client identifies itself as `dsh-codex-subscription-bridge`, not the official CLI. Account/residency headers are derived from the OAuth token; JWT claims are routing and expiry hints, not signature-verification evidence.

Model catalog compatibility queries use `99.0.0` then `0.0.0` on an empty catalog. These are not claims about an installed CLI version. This provider does not supplement live catalogs with synthetic newer slugs, offline defaults, or large-context aliases. Do not claim all ChatGPT models are available. Each visible entry additionally projects the backend-disclosed `context_window` as the model's `contextWindow` when it is a positive safe integer; a malformed value fails closed and an absent value stays omitted, so host context accounting uses only the backend's own disclosure. Every entry also projects the backend-disclosed `supported_reasoning_levels` as the model's reasoning efforts, together with `default_reasoning_level` when it names one of them, so the host offers exactly the levels that model advertises. Malformed, oversized or duplicate disclosure is omitted rather than guessed, and the selected id is forwarded verbatim because the backend, not this bridge, owns the scale.

Text is converted to Responses input. System/developer instructions are separated, and `store` is false. Harness tool definitions are validated (names, sizes, JSON object parameters) and forwarded as `function` tools with `strict: false`; the bridge never executes tools. Assistant tool calls are forwarded as `function_call` items and tool results as `function_call_output` items keyed by `call_id`. Image blocks in user messages are read through the attachment service and sent as `input_image` base64 data URLs. Non-image file attachments never reach the bridge: the Harness runtime projects file blocks to text before every adapter dispatch, so the bridge has no file-attachment handling. Reasoning blocks in replayed history are dropped, following the Harness host convention, and developer-role tool registry blocks are skipped defensively. SSE accepts bounded text, reasoning/lifecycle metadata, and completed `function_call` items; non-function execution items, refusals, malformed messages, failed/incomplete responses, and EOF without completion fail closed. Completed message items also reconcile text when terminal output is null, without duplicating earlier completion events. A completed `function_call` item is reconciled idempotently against streamed tool calls: matching name and arguments replay is accepted, anything else fails with a fixed protocol error.

## Server-side compaction

Server-side compaction is always requested when the selected model discloses a usable context window. Validated encrypted compaction items and their subsequent output window are persisted as Harness replay metadata and substituted for their exact covered input prefix. Ordinary text and tool events still go to the host. DSH local summaries and token accounting remain unchanged by default; an opt-in profile composition replaces the stock backend with `dsh-codex-subscription-bridge/compaction`, which skips this provider's routes and delegates every other provider unchanged. Existing fail-closed output rules apply to all other item types. Requests keep `store: false` and never resume a response ID. A refused checkpoint is named in the host log, and an unusable checkpoint whose full history exceeds the wire bounds fails with `COMPACTION_UNAVAILABLE`. An explicit unsupported-parameter rejection retries once with bounded full history; every other failure stays terminal. See [the implementation contract, extended retained-history bounds, fallback conditions and research](COMPACTION.md).

## Authentication lifecycle

The private dedicated directory is selected from launcher-inherited HOME, not project dotenv. Electron Desktop prefers launcher-owned DSH_HOME when set, which Desktop preserves across its login-shell environment merge. Auth helpers use the same Electron and DSH_HOME; no existing credential file is migrated. Credentials use a versioned ChatGPT-only schema. API keys are not accepted. Files are bounded to 64 KiB, opened without following symlinks, checked for ownership and permissions, and replaced atomically through private exclusive temporary files after fsync. The directory itself cannot be a symlink. Credential entries are checked before open, opened with `O_NOFOLLOW | O_NONBLOCK`, and checked again on the descriptor, so a FIFO cannot block before file-type validation.

A private directory lock serializes read-refresh-write, explicit login, and logout across processes. Waiters reread the store after acquiring the lock. Refresh begins within 120 seconds of token expiry and checks account continuity. Before dispatch, a durable `refresh_pending` state prevents replay after crashes, lost replies, malformed success responses, or persistence failures. Only a definite HTTP 429 rejection restores the prior grant for later retry. Successful persistence or explicit new login clears intent. Ambiguous outcomes require reauthentication instead of replaying the old refresh token. Terminal invalid-grant errors quarantine the local grant; rate limits do not destroy it. Raw upstream bodies never become errors. A crash after remote refresh but before durable local persistence can still require reauthentication; durable intent prevents automatic replay, but remote rotation cannot be made locally transactional.

Lock acquisition is bounded to 30 seconds. Login holds its lock while awaiting approval (at most 15 minutes); concurrent use may return `AUTH_BUSY`. Locks are not automatically stolen, because doing so can allow concurrent refresh. A crashed owner can leave `auth.lock`: stop all users of this store before manually removing that directory. A lock disappearing between an unsuccessful acquisition and its metadata check triggers another bounded acquisition attempt. Insecure locks remain rejected. No automatic lock-removal or token-export command exists.

The in-app panel reaches its endpoints through the Host's authenticated API carrier: the existing browser-session fence on Web and the trusted IPC carrier on Desktop. The initiating tab alone receives its one-time code; a random tab identifier may be kept in sessionStorage to recover ownership after reload, and no device code or tokens are stored there. Other tabs see only that a login is active, and a pending login should be closed or cancelled before discarding its tab.

## Bounds and remaining differences

Four concurrent owned operations (including cancellation cleanup), 30-second discovery deadline, 120-second turn deadline, 15-second JSON request timeout, 1 MiB JSON/event frames, 4 MiB aggregate SSE, 4096 SSE frames, 128 output text blocks, 1024 input messages with at most 64 blocks each, and 256 KiB input/output text are enforced. Tool passthrough is bounded to 256 definitions, 256 KiB aggregate, 64-character names in `[A-Za-z0-9_-]`, 8 KiB descriptions, 64 KiB JSON object parameters, 256-byte `call_id` values, 2 MiB tool outputs, and 128 blocks per output; oversize fails closed with fixed limit labels. Images are bounded to 4 MiB pixels, a 4096-pixel long edge, 1 MiB per encoded image, and 20 MiB aggregate base64 with a 10 MiB quantum; attachments are sanity-checked to 32 MiB. Oversized image requests fail with `IMAGE_OFFLOAD_REQUIRED` carrying an offload count so the Harness host can mark its oldest images offloaded and retry, and offloaded images are sent as text placeholders with zero visual tokens. JSON bodies use one fixed payload buffer and yield after bounded byte/read work, including empty fragments, so cancellation and deadline timers can run. Pre-aborted requests are rejected before store preparation. Cancelled operations retain their admission slot until owned work and cleanup settle. SSE framing is incremental, using a fixed frame buffer and bounded byte/read work batches with event-loop yields for cancellation. Cancellation aborts transport readers even if a consumer pauses. Shutdown separately waits for owned authentication/HTTP cleanup and reader cancellation with a five-second bound; unresponsive cleanup reports TIMEOUT. OAuth body reads preserve caller cancellation and deadline classification across all auth paths. Successful catalog metadata is cached in memory for 60 seconds, scoped by credential fingerprint; credentials are checked again on each lookup and each turn. In-app login requests use four exact POST endpoints on Connection's authenticated carrier with the sole Typert Gateway interceptor preserved, 4 KiB body parsing, five-second request deadlines, no-store responses, admission bounded to four, and serialized account mutations.

The initial login path is device code only. Browser PKCE fallback, keyring, credential pools, token import, quota display, and provider overrides are not included. Reasoning effort maps to Responses `reasoning.effort` `low` or `high` only. `temperature` is validated to a finite 0–2 number and forwarded; `maxTokens` is validated to a safe integer 1–1,000,000 and accepted as an advisory budget but deliberately not forwarded, matching the subscription route's adapter precedent; `stop` sequences are rejected with fixed `UNSUPPORTED_OPTION` labeling. HTTP 429 responses are classified from a bounded error body: a recognized plan usage limit (`usage_limit_reached`, `usage_not_included`, or a dsh-llm quota match) becomes terminal `QUOTA`, optionally carrying a reset hint derived only from a validated `resets_at` integer (at most one week, clamped); any other body, an unusable body, or a non-usage code stays transient `RATE_LIMIT`. The hint is the only message part derived from upstream data, and upstream text is never copied into errors. Tool execution stays in the Harness host; the bridge forwards declarations and history but never runs tools. Image acceptance on the subscription backend, per-model entitlement, and upstream acceptance of `temperature` on the subscription route are unverified. These exclusions keep the implementation reviewable and the scope small.

Real-account evidence and its limits are recorded in [verification](VERIFICATION.md). Direct connection is not evidence of official third-party service support or absence of vulnerabilities.


## Safe diagnostics

Errors retain their existing fixed codes and append only allowlisted stage labels such as `[SSE_FRAME]`, `[SSE_EVENT_UNSUPPORTED]`, `[SSE_TERMINAL]`, or `[AUTH_REFRESH_UNCERTAIN]`. Unknown labels, upstream messages, event names, credentials and identifiers are never copied into diagnostics. Failure payloads are reconstructed from the allowlists even if an Error message was mutated. Empty string text deltas are valid no-op text updates; non-string and oversized deltas remain invalid.


## Security-fixed Node baseline

Node 22.23.3 is the verified baseline (Undici 6.28.1, OpenSSL 3.5.8). Both manifests, lockfiles, and development version files specify the updated Node requirement. The public adapter and authentication CLI reject older/unverified runtimes. The exact Electron 44.0.0 / Node 24.18.1 Desktop pair is separately verified. HTTP uses bundled Undici 7.29.1 and an explicit owned Agent, preventing use of the host's older fetch implementation or shared dispatcher. Host dispatcher/proxy overrides are not inherited; these fixed HTTPS destinations must be reachable directly. This does not patch Electron/Chromium or other host features. See [Desktop verification](DESKTOP_VERIFICATION.md). No global Node installation or existing account store was migrated. [Official release](https://nodejs.org/en/blog/release/v22.23.3).
